# 《推石者》V1 的真实成片审计（修复依据）

## 检查对象
- Github Actions run 38909973592 的 `sisyphus_final.mp4`, H.264/AAC，90 s / 30 FPS，720×1280。
- 不依赖项目源码猜测：把 MP4 实际解码，抽取 0..89s 的**逐秒 90 帧**，制作三张 30 帧审计图，另在后续 V2 样片的 18–24、57–64、64–71、78–90s 抽每 0.5–0.8s 的转场序列。
- 核查对象为“旁白实际讲述的动作/概念有没有出现在同时刻的画面”，不是“任意两帧像素有没有变化”。

## V1 严重问题（从真实输出与源码双重核实）

| 时间 | 旁白 | 画面实际呈现 | 结论 |
|---|---|---|---|
| 0–18s | 受罚、不断上推、接近峰顶 | 几乎同一个人物/石头的坡面中景，推近与换构图极少 | **失去镜头节奏与劳动细节** |
| 18–24s | “巨石就会轰然滚落” | 直到**24.5 秒后**才发生主石滚落 | **动作与解说错位 ≥0.5–6.5s** |
| 24–34s | 一切重来、无奖赏、西西弗斯 | 巨石下降，但一度遮挡人物身体；没有“永无终点”的视觉反复 | **空间遮挡、意义不足** |
| 35–50s | 徒劳、荒诞英雄 | 人物+巨石构图未变，仅幽灵影子与大字标题 | **文字代替视觉论证** |
| 50–57s | “人渴望意义，世界沉默” | 仍然只有石头与人，无人/世界对立概念 | **无法不读字幕理解** |
| 57–64s | “石头总会落下” | 同一块石头在这一段**位置固定**（源代码 `rockX=455`），没有下落 | **核心画面不符** |
| 64–71s | “下一步是否迈出” | 没有真正的脚步动作；镜头仍围绕石头/人 | **没有可辨认选择瞬间** |
| 71–78s | “他看清困境” | 没有表情、眼睛或清醒的视角变化 | **抽象概念未视觉化** |
| 78–90s | 重新行动及继续向前 | 镜头与之前构图大同小异，仅背景渐亮 | **情感高潮缺少视觉变化** |

数据性佐证：V1 的 `rockX` 在 34–78s 固定为455，**约44/90秒石头世界位置未变**。每隔5秒的帧内容“不同”不能证明有完整叙事。

## 质量审查为什么失败
原来 `scripts/sisyphus_qc.py` 只检查：时长/声画流、旁白持续时间、字幕非重叠、关键帧文件是否存在、不同抽帧是否非完全相同。它**不可能**检测“18秒字幕说坠落但石头直到24.5秒才落下”。
过去把这一结果表述为“画面已通过验收”是错误的。

## V2 的 3 条不可妥协规则
1. **镜头合同**：每句旁白都要写一个 `visual.description` 和 `visual.synchronization`，并且有独立可辨认的画面内容。
2. **动作精确对应**：18–24秒坠落，57–64秒再下落，64–71秒脚实际迈出，71–78秒意识特写，78–85秒身体重新推石，动作发生在其自己的字幕时间窗。
3. **两个不同审查门槛**：自动技术审查（typecheck、编解码、时长、14场景差异）+ 人眼视觉审查（整片逐场、动作帧带、字幕与剧情对齐、石头与脚/手不穿模）；通过自动步骤不等于通过视觉步骤。

最重要的问题不是“动画代码能否运行”，而是“去掉字幕后，观众能否从镜头动作中理解这句旁白讲的意思”。
